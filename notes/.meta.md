how this repo's notes are organized and what conventions they follow.

this project's notes follow the [`reference-notes`](https://github.com/anthropics/claude-code) skill (purpose line, flat `##` sections, tables over bullets, `## metadata` footer). this file records the project-specific overrides and what each subdirectory is for.

## entrypoint

`notes/agents.md` is the file an agent or new contributor reads first. it covers the project overview, rules, architecture, conventions, and a directory index. everything else under `notes/` is referenced from it.

## layout

| path | contents |
|---|---|
| `notes/agents.md` | root agent guide; read first |
| `notes/.meta.md` | this file; notes-system conventions |
| `notes/.template.to-do.md` | starter template for a new to-do list |
| `notes/to-do.md` | open work items for the wiki, grouped by area |
| `notes/style/` | one file per convention topic (commit messages, comment voice, library usage) |
| `notes/features/` | one file per complex subsystem (scheduled tasks, etc.) |
| `notes/issues/` | bug reports and post-mortems, kept around as references |
| `notes/plans/` | multi-phase plans; managed by the `plan-create` skill, not this one |

## when to add a note

add a file to `notes/` when a topic is:

- complex enough to need more than a paragraph in `agents.md`
- stable enough not to rot week-to-week
- something an agent or maintainer would look up mid-task

heuristic: the second time you re-explain the same thing to an agent, write it down.

## file shape

every note (except the to-do lists and `agents.md`, which have their own templates) follows the `reference-notes` skill:

1. purpose line: one sentence at the top, no header above it
2. optional toc if the file is longer than one screen
3. flat `##` sections (never `####` or deeper)
4. `## see also` linking siblings, if any
5. `## metadata` last, after a `---` rule, with `last_updated: DD Month YYYY`

## project-specific overrides

| topic | rule |
|---|---|
| section headers | lowercase; proper nouns and code identifiers keep their case |
| em-dashes | never; colons for label:value, semicolons to join clauses, parens for asides |
| trailing periods | none on bullets or headers; in-sentence periods stay |
| english | american spelling |
| emoji | `:shortcode:` form, not unicode glyphs; reserved for status markers in tables and checklists |
| dates | `DD Month YYYY` (e.g. `24 May 2026`) |
| to-do statuses | `:o:` open, `:red_circle:` completed; see [.template.to-do.md](.template.to-do.md) |
